# 竞品拆解与用户研究模板

## 竞品详情页拆解表

只记录已看到的页面事实，不把“看起来转化好”当成证据。销量、评价数量、排名、转化率必须有页面或官方来源；无法确认就写“未核验”。

| 竞品/链接 | 选择理由 | 首屏承诺 | 痛点引入 | 卖点顺序 | 画面证明 | 信任背书 | 场景/对比 | FAQ/下单理由 | 可借鉴逻辑 | 不可照搬内容 |
|---|---|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |  |  |  |

### 拆解顺序

1. 首屏 3 秒内让用户知道“是什么、给谁、为什么值得继续看”。
2. 找到页面如何把用户顾虑变成一个具体问题，而不是堆功能。
3. 记录卖点出现的顺序：情绪/结果、功能/结构、材质/参数、证据、风险说明。
4. 找到信任背书的位置和证据类型：实拍、结构、细节、参数、售后、用户反馈或品牌信息。
5. 记录最后如何降低下单阻力：规格、配件、适配条件、FAQ、单件/套装、发货或购买须知。
6. 把可迁移的“页面逻辑”写成自己的句子，不复制竞品原文、品牌名、图形或场景。

## 用户痛点、顾虑与购买动机表

用户提供评价时，保留短原话；没有评价时，不能伪造用户原话，只能写“待评价验证”的假设。

| 用户原话/关键词 | 频率或来源 | 用户在意的痛点 | 最担心的问题 | 购买理由 | 可转成的页面表达 | 证据/画面 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

### 提炼规则

- “担心不真实”通常转成实拍正面/侧面/背面、细节近看和尺寸参照。
- “怕配件不对/不好用”通常转成连接结构、实际使用场景和配件清单。
- “怕太小或比例不对”通常转成手掌、包、门或桌面等真实尺度参照。
- “怕材质廉价/易损”只能写能被画面和已知资料证明的材料、结构和制作细节，不扩大成耐久承诺。
- “想送人/想要年节氛围”可以转成礼赠和场景文案，但不能虚构节日效果或官方寓意。

每次研究结束后，把结论分成：事实、评价原话、基于原话的归纳、尚未验证的推测。推测不能直接写进最终卖点。
